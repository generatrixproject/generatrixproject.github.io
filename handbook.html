Installing Generatrix by hand, from a live usb to a running system.

1. Introduction

1.1 About this handbook

This handbook walks through a manual installation of Generatrix Linux. Manual means you do every step yourself. You look at the disk, you make the partitions, you download the packages, you write the boot loader config. Nothing asks you questions and nothing happens behind your back.

That is not an accident. The minimal image ships no installer at all. If you want a program that asks you questions, use the gui image, which still carries generatrix-install.

Every command here has been run on a real system. Where a step exists for a reason that is not obvious, this handbook explains the reason instead of asking you to trust it.

1.2 What Generatrix is, briefly

Generatrix is a small independent Linux distribution. It has no gnu userland and no systemd. It is built from source on musl and busybox, uses s6 for init, clang instead of gcc, and limine to boot. There are no version numbers and no release names.

It is a rolling system. You install once. After that the whole system moves forward with one command, and that includes the kernel, the c library and init itself. There is no such thing as a Generatrix version to upgrade from.

1.3 How the installation is structured

The install has six real steps. Everything else is detail.

  1. Get on the network. The install downloads its packages, so this comes first.
  2. Prepare the disk. Partition it, put filesystems on it, mount it.
  3. Install the base system with the package manager.
  4. Finish the system. Service database, default config files.
  5. Set up the boot loader.
  6. Reboot.

If you have installed Arch or done a Gentoo stage install, this will feel familiar. The main difference is step 3: there is no tarball to unpack. The base system is a set of ordinary packages, so installing it uses the same command you will later use to install a text editor.

1.4 Before you start

You need a computer that can boot from usb, at least 64 MB of ram, a disk you are willing to erase, and an internet connection.

Note64 MB is the real floor, not a guess. The kernel decompresses itself into memory before anything else runs, and that alone needs about 40 MB. An installed system idles at around 11 to 16 MB.
WarningThis handbook erases a disk. Read the disk name twice at every step. A mistyped device name is not recoverable.

2. The installation medium

2.1 Which image

There are two x86_64 images.

The minimal image is about 12 MB. It boots to a shell and gives you the package manager and the wifi tools. It has no installer and no desktop. This handbook is written for it.

The gui image is about 18 MB. It has the same base plus hevel, a wayland compositor driven by mouse chords, and colon, a terminal written in Forth. It also carries the guided installer. You can still install it by hand with this handbook if you prefer, and ask for the desktop packages at chapter 5.

2.2 Writing the image

Write the image to a usb stick from another computer. On Linux:

lsblk
dd if=generatrix-rolling-x86_64.iso of=/dev/sdX \
    bs=4M oflag=direct conv=fsync
sync
ImportantRun lsblk first and make sure /dev/sdX is the stick and not one of your disks. dd does not warn you and does not ask for confirmation.

The image is a hybrid. The same file boots on bios and on uefi machines, and it boots from a usb stick as well as from a burned disc.

2.3 Booting and logging in

Boot the stick. You get a boot menu, then a login prompt. Type root and press enter. The live system has no password.

ImportantStay as root for the whole installation. The package manager needs it. There is also a subtler reason. busybox is installed setuid, so a shell started by an ordinary user can end up with the wrong effective user id, and then mount commands start failing with messages that do not point at the real cause.

3. Getting on the network

3.1 Why this comes first

Older Generatrix images installed by copying the live filesystem onto the disk. That is no longer how it works. The base system is downloaded from the package repository, the same way any other program is. So the network has to work before anything is written to the disk. It also means the system you install is current on the day you install it, not on the day the image was built.

3.2 Wired

If a cable is plugged in, the live system has usually already asked for an address. Check:

ip -4 addr show

If you see an inet line on an interface other than lo, you are online and can skip to chapter 4. If not, ask for a lease:

udhcpc -i eth0

3.3 Wireless

Generatrix uses eiwd, a fork of iwd built without dbus. Because there is no dbus, there is no iwctl either. A small shell helper takes its place.

First look for networks:

wifi scan

You get a table of network name, signal strength, frequency and security type. Then join one:

wifi join "My Network" "the password"

If the network is open, leave the password out.

What that command does is worth knowing, because it explains the timing. It writes the passphrase into eiwd's own store under /var/lib/iwd, then restarts eiwd so it reads the new file, then waits for the connection. eiwd keeps the network from then on. You will see two lines:

associated on wlan0, waiting for an address...
connected on wlan0 with 192.168.1.34
NoteThose two lines are separate events and there can be several seconds between them. The first means the card has joined the access point. The second means eiwd has finished dhcp and you have an address. eiwd does its own dhcp, so do not run udhcpc on a wireless interface.

If association takes a while, that is normal. Twenty seconds is not unusual.

You can check the state at any time:

wifi status

And see which networks eiwd has stored:

wifi known

3.4 Checking that it really works

An address is not the same as a working internet connection. Name resolution has to work too, and on a wireless link eiwd writes the resolver configuration a moment after it gets the address. The honest test is to use the network for what the install actually needs:

world tide

That downloads the package lists over https. If it answers indexes up to date then dns, tls and the repository are all working. If it cannot resolve the name or reach the server it says so.

4. Preparing the disk

4.1 Finding the disk

fdisk -l | grep '^Disk /dev'

Go by the size to tell your disk from the usb stick you booted from.

From here on the examples use /dev/sda. Substitute your own disk everywhere.

ImportantPartition names differ by disk type. Partitions on sda are sda1 and sda2. Partitions on an nvme disk called nvme0n1 are nvme0n1p1 and nvme0n1p2, with a p before the number. Sd cards behave like nvme, so mmcblk0 becomes mmcblk0p1.

4.2 Deciding the layout

Generatrix ships busybox fdisk, which writes mbr partition tables only. There is no gpt editor on the image. This is a deliberate limit and it is rarely a problem, because an mbr partition of type ef is accepted as an efi system partition by almost all uefi firmware.

For a bios machine you need one partition, the root.

For a uefi machine you need two, a small fat partition for the firmware to read and the root.

NoteIf your firmware is strict and refuses to boot from an mbr esp, this handbook cannot get you installed from the shipped image, because there is no gpt tool on it. That case has not come up in testing, but it is honest to say it is possible.

4.3 Creating the partitions

Start fdisk:

fdisk /dev/sda

For a bios machine, press these keys:

o     make a new empty mbr table
n     new partition
p     primary
1     partition number
2048  first sector, type this number yourself
      press enter to accept the last sector
a     mark a partition bootable
1     partition 1
w     write the table and exit

For a uefi machine:

o
n  p  1   first sector 2048, last sector +100M
t  ef     set the type of partition 1 to efi system
n  p  2   first sector 206848, last sector default
w
WarningType the first sector yourself every time. Busybox fdisk offers sector 63, not 2048. On the second partition of a uefi layout the offered 63 overlaps the first partition and produces a disk that looks fine and then fails. 206848 is 2048 plus the 204800 sectors of a 100 MB partition.

4.4 Creating the filesystems

On a bios machine there is one filesystem:

mkfs.ext4 -L generatrix /dev/sda1

On a uefi machine the first partition is the esp and the second is the root:

mkfs.vfat -F 32 -n GXEFI /dev/sda1
mkfs.ext4 -L generatrix /dev/sda2
NoteThe label is a convenience for you, not something the boot loader uses. The kernel is pointed at the disk by partition id later, for a reason explained in chapter 7.

4.5 Mounting

mkdir -p /mnt
mount /dev/sda1 /mnt

On a uefi machine the root is the second partition, so use /dev/sda2. Leave the esp unmounted for now, it is used in chapter 7.

5. Installing the base system

5.1 About world

world is the Generatrix package manager. It is one static c program with no runtime dependencies. It reads the Alpine edge repositories directly along with the Generatrix repository, resolves dependencies, and unpacks apk archives with its own gzip and tar code.

It verifies a cryptographic signature on every package and on the package index before it unpacks anything. That is why the next step copies keys.

It can install into a directory other than /. That is the whole trick behind a manual install: you point it at the disk you just mounted.

5.2 Preparing the target

mkdir -p /mnt/etc/apk /mnt/etc/world /mnt/var/lib/world
cp -a /etc/apk/keys /mnt/etc/apk/
cp /etc/world/repositories /mnt/etc/world/repositories

The first line creates the directories world expects. The second copies the trusted signing keys, both the Generatrix key and the Alpine ones. The third copies the list of repositories, so the installed system reads the same ones the live image does.

NoteThe order of the lines in the repositories file matters. The first line has the highest priority. The Generatrix repository is listed first so that our replacements for banned gnu libraries win over the Alpine originals. Do not sort that file.

5.3 What you are about to install

gx-system is a meta package. It contains no files of its own, it only depends on the pieces of a working system:

gx-musl         the c library
gx-busybox      busybox and its several hundred applet links
gx-init         s6, s6-rc, execline, mdevd
gx-base         /sbin/init, network helpers, service definitions
gx-etc          the default files for /etc
gx-kernel       the kernel
gx-boot         the limine files
gx-e2fsprogs    mke2fs and e2fsck
gx-wireless     eiwd and the scanner
world           the package manager itself

That is about 20 MB installed.

If you want the desktop as well, ask for gx-desktop instead. It adds hevel and colon and pulls in the wayland runtime, which comes to about 29 MB in total.

These are ordinary packages. Nothing in that list is special or frozen, which is why world bloom can later replace all of it, kernel included.

5.4 Installing

WORLD_ROOT=/mnt world tide
WORLD_ROOT=/mnt world seed gx-system

WORLD_ROOT=/mnt is what tells world to work on the mounted disk instead of the live system. tide downloads the package lists, seed installs. You are shown the list of packages and asked to confirm.

6. Configuring the system

6.1 Finishing the install

The files are on the disk, but the system is not assembled yet. Two things are missing. The service database has not been compiled, and /etc has no default files in it. One program does both.

Bind the kernel filesystems into the target first, because the tools it runs need them:

for d in dev proc sys; do mount -o bind /$d /mnt/$d; done
chroot /mnt /usr/libexec/gx-refresh

gx-refresh does three jobs:

  1. It copies the default files into /etc where they are missing. It never overwrites a file that already exists, so running it again later is safe and your edits survive package upgrades.
  2. It compiles the s6 service database from /etc/s6-rc/source. If the compile fails it keeps the previous database rather than leaving you with none.
  3. After a kernel upgrade it saves the previous kernel and adds a second boot entry pointing at it.
NoteThat third job is the reason shipping the kernel as a package is safe. A kernel that does not boot leaves the old one in the boot menu.

This same program runs automatically after every package install on a running system. It is also how gtk cache files, font caches and mime databases get rebuilt.

6.2 The filesystem table

The kernel finds the root partition by the disk identifier, so the disk needs one. Busybox fdisk does not write it, so give the disk an identifier yourself. It is four random bytes at offset 440 of the disk:

dd if=/dev/urandom of=/dev/sda bs=1 count=4 seek=440 \
    conv=notrunc
WarningRun that on the whole disk, /dev/sda, not on a partition. It writes inside the boot sector, ahead of the partition table, and it does not touch your partitions.

Now read it back:

dd if=/dev/sda bs=1 skip=440 count=4 2>/dev/null | od -An -tx1 |
    awk '{printf "%s%s%s%s\n",$4,$3,$2,$1}'

You get eight hex digits, something like 34db77b7. The bytes are printed in reverse because that is the order the kernel reads them in. Your first partition is then 34db77b7-01 and the second is 34db77b7-02.

printf 'PARTUUID=34db77b7-01 / ext4 rw,relatime 0 1\n' \
    > /mnt/etc/fstab

6.3 Hostname and password

echo mymachine > /mnt/etc/hostname
chroot /mnt passwd root

6.4 Timezone and keyboard

These are optional. If the target has a zoneinfo directory:

chroot /mnt ln -sf \
    /usr/share/zoneinfo/Europe/Istanbul /etc/localtime

The console keymap and the wayland keyboard layout are two different things. The console reads a compiled keymap file, wayland reads an environment variable. If you install the desktop later and your keyboard is not us, set both.

6.5 Carrying your wifi over

If you set up wireless in chapter 3, the installed system can keep it:

mkdir -p /mnt/var/lib/iwd
cp -a /var/lib/iwd/. /mnt/var/lib/iwd/

eiwd will find the network and connect at boot.

7. The boot loader

7.1 How Generatrix boots

Generatrix uses limine. There is no initramfs on an installed system. The kernel mounts the root filesystem itself and runs /sbin/init directly.

That single fact drives everything in this chapter, so it is worth stating plainly. Nothing runs before the kernel mounts the disk. There is no early userspace to look up disk labels, load modules or ask questions.

7.2 Bios

mkdir -p /mnt/boot/limine
cp /mnt/usr/share/limine/limine-bios.sys /mnt/boot/limine/
cat > /mnt/boot/limine/limine.conf <<'EOF'
timeout: 2
/Generatrix Linux
    protocol: linux
    kernel_path: boot():/boot/vmlinuz-generatrix
    cmdline: root=PARTUUID=34db77b7-01 ro mac80211_hwsim.radios=0
EOF
chroot /mnt limine bios-install /dev/sda
ImportantRun the installed system's own limine, through chroot, not the one on the live image. The boot loader is in two pieces: the small piece bios-install writes into the boot sector, and limine-bios.sys on the disk. The two are checked against each other at boot and must come from the same build. If they do not match, the machine stops with "limine-bios.sys build ID mismatch" before the kernel ever starts. The chroot needs /dev inside the target, which chapter 6.1 already mounted for you.

7.3 Uefi

mkdir -p /mnt/esp
mount /dev/sda1 /mnt/esp
mkdir -p /mnt/esp/EFI/BOOT /mnt/esp/boot/limine
cp /mnt/usr/share/limine/BOOTX64.EFI \
    /mnt/esp/EFI/BOOT/BOOTX64.EFI
cp /mnt/boot/vmlinuz-generatrix /mnt/esp/boot/
cat > /mnt/esp/boot/limine/limine.conf <<'EOF'
timeout: 2
/Generatrix Linux
    protocol: linux
    kernel_path: boot():/boot/vmlinuz-generatrix
    cmdline: root=PARTUUID=34db77b7-01 ro mac80211_hwsim.radios=0
EOF
umount /mnt/esp

There is no limine bios-install step on uefi. The firmware loads EFI/BOOT/BOOTX64.EFI by itself.

7.4 The command line, explained

Three things in that cmdline are load bearing. Put your own disk id in place of 34db77b7 and leave the rest alone unless you know what you are changing.

root=PARTUUID=...

The kernel has to find the root filesystem with nothing else running. It can read a partition id out of the partition table on its own. It cannot resolve a filesystem label or a filesystem uuid, because those live inside the filesystem and something has to read them first. On a system with an initramfs that something exists. Here it does not.

If you write root=LABEL=generatrix the machine stops with VFS: Unable to mount root fs on unknown-block(0,0).

ro

/sbin/init runs e2fsck on the root filesystem and then remounts it read write. e2fsck refuses to check a filesystem that is already mounted read write, which is correct of it. If you boot with rw the check fails and init drops you into a repair shell.

mac80211_hwsim.radios=0

The kernel includes the mac80211 wireless simulator. Left alone it creates two fake radios at boot. On a machine with a real card this pushes the real interface to wlan2, and the wifi helper, which looks at wlan0 first, stops finding it. Setting the option to zero keeps the simulator quiet.

8. Rebooting

Unmount everything in the right order and restart:

umount /mnt/dev /mnt/proc /mnt/sys
umount /mnt
reboot

Take the usb stick out while the machine restarts.

You should get the limine menu, then a login prompt with your hostname. Log in as root with the password you set.

9. After the installation

9.1 Keeping the system current

world tide
world bloom

bloom upgrades everything that is installed, and on Generatrix that really does mean everything. The kernel, the c library, busybox, init and the package manager itself are all packages, so they all move with this one command.

NoteWhen the kernel is replaced the previous one stays on disk and a second boot menu entry appears for it. If a new kernel does not boot on your hardware, pick the previous entry in the menu and carry on.

9.2 Adding the desktop

world seed gx-desktop

9.3 Installing other software

world reads the Alpine edge repositories, so most of that catalogue is available:

world map firefox
world seed firefox

Some of it refuses to install, on purpose:

error: bash is gnu software. gnu does not run on generatrix.

That is not a bug. Generatrix bans gnu software by name. Where a program needs a gnu library, the distribution ships its own non gnu implementation under the same name and the same interface, so the program installs and runs with no gnu code anywhere. Where the program itself is gnu, it is refused.

9.4 Command reference

world tide            refresh the repository indexes
world seed <pkg>      install
world bloom           upgrade everything
world weed            remove packages nothing needs any more
world map <pattern>   search
world probe <pkg>     show details about a package
world grove           list what is installed
world vaporize <pkg>  remove

10. If something goes wrong

limine-bios.sys build ID mismatch

The boot loader stops before the kernel starts. The piece in the boot sector and the limine-bios.sys on the disk come from different builds. Redo the boot loader step with the installed system's own limine, chroot /mnt limine bios-install /dev/sda, and make sure /mnt/boot/limine/limine-bios.sys was copied from /mnt/usr/share/limine, not from the live image. See 7.2.

Kernel panic: Attempted to kill init

The kernel found and mounted the root filesystem but could not run /sbin/init. Check that root= points at the right partition, and that /sbin/init exists on it and can be executed.

Kernel panic: VFS: Unable to mount root fs

The kernel could not find the root filesystem from your root= setting. Nearly always this is a LABEL= or UUID= where a PARTUUID= is required. See 7.4.

Boot ends in a repair shell and fsck failed

The command line says rw. Change it to ro. See 7.4.

world cannot fetch a repository index

world skips a repository it cannot reach and continues with the others, so this only stops the install when none of them answer. Check the network with the test in 3.4.

Wifi saved the network but never connects

Give it up to a minute. Association and dhcp are separate steps and the second is silent until it succeeds. wifi status shows the interface state and whether it has an address. wifi known lists what eiwd has stored.

The wireless interface is called wlan2 and nothing works

The kernel wifi simulator created two fake radios. Your command line is missing mac80211_hwsim.radios=0. See 7.4.

Programs have no text in their menus after installing a desktop

Run world bloom once. Toolkits like gtk need cache files that are generated after installation. Current versions of world build them for you.
