Generatrix Linux

Radically Anti-GNU

generatrix linux

a small, independent linux distribution with no gnu and no systemd. built from source, from scratch, on musl and busybox. rolling, no version numbers, no codenames. the whole live-and-installable system fits in a 12 mb iso. once installed it idles at 13 mb of ram, measured, not guessed. it wants about 64 mb in the machine to boot though, the kernel unpacks itself into ram before anything else runs.

frequently asked questions

these are some supposedly frequently asked questions.

what is generatrix?

a linux distribution built by removing things instead of adding them. no gnu userland, no systemd, no dbus, no base system to fight against. musl libc, busybox, s6 for init, clang instead of gcc, limine to boot. that's basically the whole thing.

is generatrix stable?

mostly. it installs and boots on real bios and uefi hardware, wifi works, the package manager works. but it's getting developed by 3 person(me, I and myself)

should i install generatrix?

Yeah you need to install generatrix because

  • its lighter than tinycore
  • its better than BigRatOS
  • reliable and small distro

is modern browsers, games and other shit available on generatrix?

probably. world installs standard alpine .apk packages from the alpine edge repos, so most of the alpine catalogue works. if it's gnu software though, no. see below.

is generatrix gnu/linux?

no. that's the entire point.

what's world?

world is our package manager. it's one ~1000-line c program, a single static binary, no runtime dependencies. it reads alpine's edge repos directly, resolves dependencies, and unpacks the .apk archives itself with its own gzip and tar code instead of shelling out to tar. it also unpacks safely, it won't let a package write outside the target or overwrite files through a symlink.

it has a growth-themed cli because why not:

world tide            refresh the repo indexes
world seed <pkg>      install
world bloom           upgrade everything
world weed            remove orphaned dependencies
world map <pattern>   search
world probe <pkg>     info
world grove           list installed
world vaporize <pkg>  remove

so how does it block gnu?

if you ask world to install gnu software it just refuses:

error: bash is gnu software. gnu does not run on generatrix.

it also swaps a few bloated non-gnu tools for leaner ones on its own, like meson for muon, ninja for samurai, sudo for doas, man-db for mandoc. and it turns away lisps for having too many parentheses. that last one is a joke, but it's also real, it will actually refuse to install sbcl.

but doesn't banning gnu break half the software you'd want to install?

it would, if we stopped at the ban. a lot of programs need a gnu library somewhere down the chain, so banning the library would drag the whole program down with it.

so we don't just ban them, we replace them. when a program needs a banned gnu library, we write our own non-gnu version that answers to the same name and the same abi, ships zero gnu code, and gets tested against the real library so it behaves the same. the program links against ours and never knows the difference.

so far we've done:

libtasn1        our own clean-room asn.1 engine, checked against real
                libtasn1 on actual x.509 certificates
libunistring    backed by utf8proc, matched across every unicode codepoint
readline        libedit
gettext/iconv   musl already does these, we just answer to the old names
fribidi         sheenbidi
ncurses         netbsd-curses

the gnu tls stack that printing and networking drag in gets rebuilt on openssl instead

the gnu ban stays total and your software still installs. no gnu code ships.

how big is it really?

the minimal iso is 12 mb. a fresh install idles at 13 mb of ram. the live image itself sits at 19 mb, because it keeps its filesystem in memory. you still want 64 mb or more in the box, because the kernel decompresses into memory first and that alone is 40 mb. there's also a 64-bit gui edition, which is a plan-9-style floating wayland compositor called hevel driven by mouse chords. hevel's sourcehut page for supporting the whole gui iso is 17 mb, and it idles at 23 mb with the compositor running.

does it do uefi?

yes, and bios, from the same image. the gui edition's installer detects your firmware and sets up the right boot partition either way. it's a plain openbsd-style question and answer installer, no tui art, no mouse. the minimal edition has no installer at all, you do it by hand with the handbook.

what license is generatrix under?

the whole repository is bsd 2-clause plus patent. take it, fork it, ship it, sell it, doesn't matter. it is also, unlike some distributions, not available for 7.5 thousand dollars per sku.

what it looks like

the limine boot menu, and the gui edition: hevel, three havoc terminals, the installer, and world turning down bash.

changelog

rolling, so there are no releases to number. these are the dates things actually changed.

august 2026

  • the 32-bit build is gone. generatrix is 64-bit only from now on. it was a toy from the start, it never had the package manager, and keeping a second kernel and a second toolchain alive was work that bought nobody anything.
  • generatrix rolls all the way down now. the kernel, the c library, busybox, the s6 init programs, e2fsprogs, the wifi programs, the boot loader files and the init scripts are all ordinary packages. before this they were written into the image by the build and then frozen at install time. you install once and world bloom moves the whole system forward, kernel included.
  • you can install by hand, with no installer at all: 
    WORLD_ROOT=/mnt world seed gx-system
chroot /mnt /usr/libexec/gx-refresh
    that gives you a complete system in about 20 mb. ask for gx-desktop instead if you also want the wayland desktop.
  • world can replace itself while it is running.
  • a kernel update keeps the old kernel and adds a second boot entry for it, so a broken kernel cannot lock you out.
  • the installer sets up the network first, because it downloads its packages now instead of copying the live image. if a cable is plugged in it just uses it. if not, it scans for wifi with our own eiwd, shows you the networks, asks for the one you want and its password, and lets eiwd save it.
  • the minimal image no longer ships an installer. that one is by hand or not at all. there is a handbook for it.
  • world skips a repository it cannot reach and carries on with the others. it used to stop, which was enough to break an install.
  • fixed: the installer installed almost nothing. when world was pointed at another root it still read the package database of the running system, so every package the live image already had was counted as installed and skipped. the new system came out without world itself, without the wayland libraries and without a package database of its own. WORLD_LIB and WORLD_REPOS now follow WORLD_ROOT. a fresh install is 37 packages and about 21 mb of /usr again.
  • fixed: on an installed system three services never started. the s6 helper that runs one-shot services was not in any package, so loopback stayed down, device coldplug never ran and the console keymap was never loaded. the init package is now built from the list of files the s6 build actually installs, not from a list typed by hand, which is also how twenty six more execline programs found their way in.
  • fixed: a system installed by hand stopped at "limine-bios.sys build ID mismatch" before the kernel started. the boot loader is in two pieces and they have to come from the same build. the boot loader is now installed with the new system's own limine, and that program ships in a package instead of only existing on the live image.
  • fixed: a base install with no desktop kept trying to start the compositor and failing, because the service description was in the base package. it belongs to hevel now.
  • the handbook was wrong in two places and has been corrected. busybox fdisk offers sector 63, not 2048, and it writes no disk identifier at all, so the handbook now tells you to create one. both were found by running the handbook from top to bottom in a virtual machine and booting what came out.
  • fixed: colon showed only the first lines of a program and never scrolled. the terminal was telling programs its height and width the wrong way round, so they wrote to lines that were off the screen.
  • fixed: caps lock, alt gr and num lock did nothing in colon. it was reading only one of the three modifier fields wayland sends, and it only ever looked at the first two levels of the keymap, so the alt gr symbols on a turkish layout were out of reach.
  • the gui edition has its own terminal now. colon is written in forth, it is about 92 kb, it is statically linked and it links nothing but libc - no libwayland, no libxkbcommon, no freetype, no fontconfig. it speaks the wayland protocol on the socket itself and rasterises its own truetype glyphs. havoc is gone.
  • colon starts on a dark palette, and the compositor paints a pastel sage background instead of the old teal.
  • world tells you where every package comes from now: 
    alpine/edge/main/busybox
alpine/edge/community/gtk+3.0
gx-repo/fribidi
  • world rebuilds the caches that alpine's package triggers would normally build: glib schemas, gdk-pixbuf loaders, the mime database, font caches. no package script is ever executed, it just runs the cache builders if they are there.
  • fixed: the live image booted from a cd but panicked when booted from a usb stick. the initramfs believed findfs, which pointed it at a 68 kb partition that merely looked like the iso filesystem from the outside. it now insists that the squashfs really mounts before it accepts a device.
  • fixed: every executable bit in the repository had been lost in an upload, so /sbin/init was not executable and the kernel gave up with "attempted to kill init". the build sets the bits itself now and refuses to produce an image if init cannot be executed.
  • fixed: the repository list shipped empty, so world had nothing to index and nothing to install.
  • fixed: firefox drew its whole interface with no text in it. it was not a font problem. without the compiled glib schemas gtk could not work out the screen dpi, reported it as -1, and firefox duly laid out every menu and the address bar at a negative font size. the cache rebuild above is the fix.
  • fixed: our netbsd-curses laid out cchar_t differently from ncurses, so wide-character programs like htop drew their labels and then nothing else. the struct matches byte for byte now.
  • fixed: curl was configured as if it were being built natively instead of cross, and the libcurl that came out had no ca bundle path compiled in.
  • fixed: two keyboard bugs in colon. the keymap size was read from the wrong offset, because file descriptors take no room in a wayland message, and numeric keysyms were not understood at all.

july 2026

  • packages and the repository index are signed, and world verifies both before it unpacks anything. a tampered package is refused.
  • the package repository moved online, which is what made the images small.
  • uefi boot, for the live image and for installs, from the same file as bios.
  • more gnu libraries answered by non-gnu code: a clean-room asn.1 engine for libtasn1, utf8proc behind libunistring, punycode and idna2008 for libidn2, libedit behind readline, and musl answering for gettext and iconv.
  • the images got a lot smaller: the minimal one went from 18.4 to 12.4 mb.
